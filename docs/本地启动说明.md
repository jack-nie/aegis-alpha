# 本地启动说明

本地开发的启动 / 停止 / 状态 / 日志统一由一个入口管理：

| 平台 | 入口 |
|------|------|
| Linux / macOS / Git Bash | `./aegis.sh` |
| Windows PowerShell 5.1+ / PowerShell 7 | `.\aegis.ps1` |
| Windows cmd / 双击 | `aegis.cmd`（转发到 `aegis.ps1`；双击不带参数时执行 `up` 并保留窗口） |
| make | `make up` / `make down` / `make status` / `make logs SERVICE=web` …（转发到 `./aegis.sh`） |

两个脚本的子命令和行为一致，下文以 `./aegis.sh` 为例，PowerShell 把 `--xxx` 换成 `-Xxx` 即可。

## 常用命令

```bash
./aegis.sh up                    # 按 orchestrator -> backend -> web 顺序启动，逐个等待健康检查
./aegis.sh up backend web        # 只启动指定服务（orchestrator | backend | web | all）
./aegis.sh status                # 进程 PID、端口、健康检查返回码
./aegis.sh logs                  # 各服务最近 80 行日志；-f 持续跟踪，-n 200 指定行数
./aegis.sh logs backend -f
./aegis.sh restart web --web-mode prod   # 先停再起；prod = npm run build + next start
./aegis.sh down                  # 按 web -> backend -> orchestrator 停止本脚本启动的全部进程
./aegis.sh smoke                 # 冒烟检查（前端 200、后端未登录 401/403、orchestrator health 与令牌鉴权）
./aegis.sh setup                 # 安装依赖：orchestrator .venv（按 constraints.txt）、web node_modules、backend 编译
./aegis.sh infra up              # 用 docker compose 只启动 mysql + redis（infra down / infra status）
```

PowerShell 对应：`.\aegis.ps1 up`、`.\aegis.ps1 down backend`、`.\aegis.ps1 logs web -Follow -Lines 200`、
`.\aegis.ps1 restart -WebMode prod -NoBrowser`、`.\aegis.ps1 up -SkipInstall -Force`。

服务别名：`orch` / `langgraph` = orchestrator，`api` = backend，`frontend` / `fe` = web。

## 端口与健康检查

| 服务 | 端口 | 启动命令 | 就绪判定 | 超时（秒，可用环境变量改） |
|------|------|----------|----------|------|
| orchestrator | 8787（`AEGIS_ALPHA_LANGGRAPH_PORT`） | `python -m uvicorn app.main:app --host 127.0.0.1` | `GET /health` 返回 200 | 60（`AEGIS_ORCHESTRATOR_TIMEOUT`） |
| backend | 5178（`AEGIS_ALPHA_PORT`） | `mvn spring-boot:run -Dspring-boot.run.profiles=local` | `GET /_backend/auth/me` 有 HTTP 响应（未登录 401 即就绪） | 300（`AEGIS_BACKEND_TIMEOUT`） |
| web | 5174（`AEGIS_ALPHA_FRONTEND_PORT`） | `next dev`（默认）或 `next build` + `next start` | `GET /` 返回 2xx–4xx | 180（`AEGIS_WEB_TIMEOUT`） |

- orchestrator 默认只监听 127.0.0.1，需要局域网访问时设 `AEGIS_ORCHESTRATOR_BIND_HOST=0.0.0.0`。
- Spring profile 默认 `local`（会读取 gitignore 的 `application-local.yml`，不存在也没关系），可用 `AEGIS_SPRING_PROFILES` 覆盖。
- 前端 `next.config.mjs` 把 `/_backend` 固定代理到 `127.0.0.1:5178`，改 backend 端口时脚本会提示。
- MySQL（3306）/ Redis 不由脚本管理；未监听时脚本只给警告。可用 `./aegis.sh infra up` 或自行安装。

## 运行时文件

| 路径 | 内容 |
|------|------|
| `.run/<服务>.pid` | 本脚本启动的进程 PID（进程组 leader），`down` 只结束这些进程及其子进程 |
| `.run/secrets.env` | 未配置时自动生成的本地服务令牌与签名密钥（权限 600，已 gitignore） |
| `logs/<服务>.log` | 服务日志，重新启动时上一份改名为 `.log.1`；Windows 下 stderr 在 `logs/<服务>.err.log` |

`.run/` 和 `logs/` 均已在 `.gitignore` 中。

## 环境变量与 .env

- 默认读取仓库根目录 `.env`（`--env-file <文件>` 或 `AEGIS_ENV_FILE` 可改）。按 `KEY=VALUE` 逐行解析，**不会 `source`**，
  因此 JDBC URL 里的 `&` 等字符不会出问题；当前 shell 里已有的非空变量优先（Windows 下用户级环境变量也优先于 `.env`）。
- `.env.example` 是给 docker compose 的：脚本会把其中的 compose 主机名改成本机（`//mysql:` → `//127.0.0.1:`，
  `AEGIS_ALPHA_REDIS_HOST=redis` → `127.0.0.1`），并把 `AEGIS_ALPHA_LANGCHAIN_ENGINE_URL` / `AEGIS_ALPHA_BACKEND_URL`
  固定指向本机端口，所以同一份 `.env` 两种方式都能用。
- `AEGIS_ALPHA_NODE_EXECUTION_TOKEN` / `AEGIS_ALPHA_TOKEN_SECRET` 未配置时生成随机值写入 `.run/secrets.env`，
  orchestrator 和 backend 用同一份。脚本**不再使用示例令牌 `local-workflow-node-token`，也不再设置
  `AEGIS_ALPHA_DEV_MODE=true`**，也不内置任何数据库 / Redis 密码（未配置时沿用 `application.yml` 的默认值）。
- 没有 `AEGIS_ALPHA_LANGCHAIN_API_KEY` / `OPENAI_API_KEY` 且未显式设置 `AEGIS_ALPHA_LANGCHAIN_MOCK` 时，
  自动使用 `AEGIS_ALPHA_LANGCHAIN_MOCK=true`，不配模型 key 也能跑通。
- 生产标记（`AEGIS_ALPHA_ENV=prod|production` 或 `SPRING_PROFILES_ACTIVE` 含 prod）下如果同时有
  `AEGIS_ALPHA_DEV_MODE=true`、示例服务令牌或 demo `AEGIS_ALPHA_TOKEN_SECRET`，脚本在启动前就报错退出
  （与 `ProductionSafetyGuard` / orchestrator `production_safety_problems` 同一规则）。本脚本只面向本地开发，生产用 docker compose（CI 部署走 `scripts/deploy-production.sh`：build + `up -d` + 等待健康检查）。
- `AEGIS_ALPHA_REPLICAS>1` 时脚本提示：本地只起一个 orchestrator 进程；未设
  `AEGIS_ALPHA_ALLOW_LOCAL_BACKENDS_MULTI_REPLICA=true` 时 orchestrator 会拒绝启动（见 [多副本设计.md](多副本设计.md)）。
- `AEGIS_ALPHA_SQL_INIT` 等其余变量原样传给服务。

## 端口占用与停止

- `up` 前检查端口：端口被本脚本记录的进程占用且健康 → 跳过（重复执行 `up` 是安全的）；
  被其他进程占用 → 报错并给出 PID，加 `--force`（PowerShell `-Force`）才会结束该进程。
- `down` 先 TERM 整个进程组（mvn fork 出的 java、npm/next 子进程一起），15 秒后仍未退出再 KILL（Windows 用 `taskkill /T /F` 结束进程树）；
  端口仍被外部进程占用时只提示，加 `--force` 才结束。
- 某个服务启动失败（进程退出或超时）时脚本打印日志末尾并返回非 0；已启动的服务保持运行，修复后再次 `up` 即可。

## 旧脚本与新命令对照

旧的分散脚本已全部删除：

| 旧命令 | 新命令 |
|--------|--------|
| `bash restart-local.sh` | `./aegis.sh restart`（旧脚本不起前端；新命令默认三个都起，只要后端两项用 `./aegis.sh restart orchestrator backend`） |
| `.\restart-local.ps1` | `.\aegis.ps1 restart` |
| `.\stop-local.ps1` | `.\aegis.ps1 down`（旧脚本按端口强杀；等价为 `.\aegis.ps1 down -Force`） |
| `.\start-aegis-alpha.ps1` | `.\aegis.ps1 up -WebMode prod`（旧默认先 build 前端；新默认 `next dev`，直接 `.\aegis.ps1 up`） |
| `.\start-aegis-alpha.ps1 -FrontendDev` | `.\aegis.ps1 up` |
| `.\start-aegis-alpha.ps1 -SkipLangGraph` | `.\aegis.ps1 up backend web` |
| `.\start-aegis-alpha.ps1 -SkipInstall -NoBrowser` | `.\aegis.ps1 up -SkipInstall -NoBrowser` |
| `.\start-aegis-alpha.ps1 -BackendPort 5179` 等端口参数 | 环境变量 `AEGIS_ALPHA_PORT` / `AEGIS_ALPHA_FRONTEND_PORT` / `AEGIS_ALPHA_LANGGRAPH_PORT` |
| `.\start-aegis-alpha.ps1 -BackendTimeoutSeconds 300` | 环境变量 `AEGIS_BACKEND_TIMEOUT=300` |
| `start-aegis-alpha.bat` / `start-aegis-alpha-langchain.bat`（双击） | 双击 `aegis.cmd`，或 `aegis.cmd up` |
| `stop-aegis-alpha.bat` | `aegis.cmd down` |
| `.\stop-aegis-alpha.ps1` | `.\aegis.ps1 down`（需要强杀端口占用者时加 `-Force`） |
| `.\stop-aegis-alpha.ps1 -DryRun` | `.\aegis.ps1 status` |
| `.\stop-aegis-alpha.ps1 -IncludeLegacy` | 无（5173/5177/4173 旧端口已不再使用） |
| `.\restart-aegis-alpha.ps1` | `.\aegis.ps1 restart -WebMode prod` |
| `.\aegis-alpha-orchestrator\setup-venv.ps1` | `.\aegis.ps1 setup orchestrator` |
| `.\scripts\health-check.ps1` | `.\aegis.ps1 smoke`（或直接 `.\scripts\smoke-aegis-alpha.ps1`） |
| `node scripts/mock-langgraph.mjs` | 不再需要：真实 orchestrator 在无 key 时自动 mock（`AEGIS_ALPHA_LANGCHAIN_MOCK=true`） |

保留的脚本：`scripts/smoke-aegis-alpha.ps1`（冒烟检查，`aegis.ps1 smoke` 调用它）、`scripts/loadtest_help.py`、
`scripts/remote_exec.py`（与本地启动无关）。
